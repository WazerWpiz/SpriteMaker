2. Design tokens (ganti hardcoded)

Definisikan sekali di ui/RespriteTheme.kt sebagai ColorScheme Compose, lalu semua komponen memakai token.

bg #14161a surface #1c1f26 surface2 #232833 fg #e8e6e1 accent #ffb454 accent2 #4ec9b0 muted #8b93a1 line #2e3440

Pasangan tipografi: Inter untuk label/UI, JetBrains Mono untuk koordinat, ukuran kanvas, dan angka frame. Angka pakai font-feature-settings:"tnum" agar sejajar.

4. Spesifikasi komponen

Tool chip

  • Ukuran sentuh ≥ 44dp, jarak antar chip 6dp.
  • Aktif: latar accent, ikon warna bg, sudut 10dp.
  • Non-aktif: surface2 + border line.
  • Hanya tool yang punya handler ditampilkan.

Layers sheet

  • Dibuka dari tombol di footer, muncul sebagai ModalBottomSheet.
  • Setiap baris: nama, ikon mata (visibilitas), ikon kunci, slider opacity.
  • Opacity/lock/visibility memakai command yang sudah ada di SpriteCommands.kt — cek dulu sebelum menambah.

Canvas

  • Checkerboard pakai token surface2 gelap/terang, bukan warna acak.
  • Overlay grid saat zoom ≥ 8×.
  • Status bar kecil: koordinat pointer + ukuran kanvas, font mono, warna muted.

5. Urutan kerja yang realistis

  1. Tokens dulu — pindahkan semua warna hardcoded ke RespriteTheme.kt. Tidak ada perubahan perilaku, hanya konsistensi.
  2. Sembunyikan tool mati — buang Select/Gradient dari UI sampai ada handler.
  3. Tool chip aktif — indikator jelas pada tool terpilih.
  4. Layers → sheet — bebaskan lebar kanvas di layar sempit.
  5. Status bar kanvas — koordinat + zoom.
Kenapa urutan ini: langkah 1–3 tidak menyentuh logika gambar/undo sama sekali (risiko rendah, dampak visual tinggi). Sheet dan status bar menyentuh layout, jadi dikerjakan setelah fondasi token stabil.

6. Yang sengaja TIDAK dilakukan

  • Tidak menambah fitur baru (animasi, GIF, select/crop) — itu di luar desain scaffold ini.
  • Tidak meniru visual Flutter asli secara persis — HANDOVER sudah menyatakan itu pekerjaan berbulan-bulan.
  • Tidak menyentuh CanvasView.kt gesture logic — HANDOVER §5 poin 5–6 melarang mengubah pola itu.
